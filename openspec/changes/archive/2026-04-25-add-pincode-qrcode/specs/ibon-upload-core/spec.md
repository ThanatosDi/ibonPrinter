## ADDED Requirements

### Requirement: In-memory QR Code generation from pincode

The core client SHALL generate a QR Code image in memory from the pincode returned by ibon, attach the raw PNG bytes plus its base64-encoded string to the result, and never write the QR Code to disk inside the client.

#### Scenario: Happy-path QR Code is attached to the result
- **WHEN** `upload(...)` succeeds and the client receives a pincode (e.g. `"1234567890"`)
- **THEN** the returned result's `qrcode_png` field SHALL contain PNG image bytes whose first 8 bytes are `b"\x89PNG\r\n\x1a\n"`
- **AND** the result's `qrcode_base64` field SHALL contain a non-empty ASCII string whose `base64.b64decode(...)` value equals `qrcode_png` byte-for-byte
- **AND** the QR Code SHALL encode exactly the pincode string (no URL or JSON wrapping)

#### Scenario: QR Code is decodable by an independent QR scanner
- **GIVEN** the test fixture at `tests/qrcode_example.png` (an ibon-rendered QR Code that decodes to `"3524627893"`)
- **WHEN** the client invokes its in-memory QR Code generator with the same pincode `"3524627893"`
- **THEN** decoding the produced PNG bytes with an independent QR scanner (e.g. pyzbar) SHALL also yield `"3524627893"` — proving round-trip equivalence with the ibon-rendered example, not just self-consistency

#### Scenario: QR Code generation failure does not abort upload
- **WHEN** the QR Code generation step raises an unexpected exception (e.g. environment problem)
- **THEN** the client SHALL emit a `warnings.warn(...)` and still return the result with valid `pincode` and `deadline`
- **AND** the result's `qrcode_png` SHALL be `b""` and `qrcode_base64` SHALL be `""`

## MODIFIED Requirements

### Requirement: Typed result object

The core client SHALL return a frozen dataclass (or `TypedDict`) rather than a raw dict so callers get attribute access and IDE autocomplete.

#### Scenario: Result shape
- **WHEN** `upload(...)` succeeds
- **THEN** the returned object exposes `.pincode: str`, `.deadline: datetime`, `.qrcode_png: bytes`, `.qrcode_base64: str`, `.raw: dict` fields
- **AND** `qrcode_png` is the raw PNG image bytes generated by the client from the pincode (not the base64 string)
- **AND** `qrcode_base64` is the standard-base64 encoding of `qrcode_png` (without any `data:image/png;base64,` URI prefix)
